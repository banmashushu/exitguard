# ExitGuard 本机代理：快速开始

此版本可直接接入 HTTP、HTTPS 或 SOCKS5 上游，不要求安装系统过滤。你仍需提供一个从当前网络可达的代理服务；软件本身不提供公网 IP。

## 打开

- Mac：先退出旧版 ExitGuard，再打开压缩包中的 `ExitGuard.app`。
- Windows x64：完整解压后，双击 `Start-ExitGuard.cmd`，保留命令窗口。无需管理员权限。

## 配置并启动

1. 打开“代理设置”。运行方式选择 **代理转发**，出口来源选择 **远程代理**。
2. 填写服务商提供的类型、服务器和端口，点击底部“保存并暂停会话”。只填服务器地址，不把用户名密码塞进地址。
3. 需要认证时，填写账户密码并点击“提交会话账户”。凭据只保存在本次运行的内存中；退出后需要重新填写。
4. 回到“出口概览”，点击“测试候选 IP”。确认结果符合服务商提供的固定出口后，回设置中手动填写“期望公网 IPv4”并保存。
5. 点击“检查出口”，成功后点击“启动代理”。本机 HTTP 代理地址默认为 `127.0.0.1:17890`。
6. 将支持代理的应用配置为使用该本机地址，或在“可选：浏览器 / Claude 启动路径”中添加实际程序路径，再从概览启动专用窗口。

如果已有配置仍显示严格阻断，这是为了保留旧配置的保护要求；要使用普通代理，需要明确改选“代理转发”。

## 选择正确的代理类型

- **HTTP**：通过 HTTP CONNECT 建立目标 HTTPS 隧道。到代理本身的链路没有 TLS。
- **HTTPS**：到代理服务器的这一段也使用 TLS，必须能通过正常证书验证。
- **SOCKS5**：支持无认证或用户名/密码认证；SOCKS5 本身没有 TLS。

服务商写“支持 HTTPS 网站”不一定表示代理端口自身启用了 TLS。按其实际连接协议填写，协议不匹配时不要忽略证书或改安全设置。

## 这版的实际范围

- 只转发明确经过本机入口的 IPv4 TCP；不处理 UDP，也不能强迫所有程序采用代理。
- 暂停、配置变化、认证失败或出口检查失败会关闭本应用持有的连接；不会主动退回直连目标。
- 出口监测存在检测时间窗口。检测到的 IP 是探测请求的出口，实际客户端仍要验证。
- Chrome / Edge 启动入口使用独立资料目录和明确代理参数。Claude 是否完整采用参数需对当前客户端实测；浏览器或程序忽略代理的流量不受普通模式约束。
- **代理运行中不等于系统防绕行已启用。** 严格阻断仍需另行部署和验收；如果以前装过持久规则，切回普通代理也不会自动移除它们。
- 本地协议、HTTP/HTTPS 转发、认证、暂停与断线测试已通过；未使用你的第三方代理或 Claude 账号进行实测。Windows 产物目前为交叉编译版本。

代理密码不用发到聊天中。公司飞连及网络策略保持原状；若当前网络不能连接上游，需要先解决可达性，软件不会绕过公司的路由控制。
