# Optional Pre-Proxy Implementation Plan

> **For agentic workers:** Use the astra-sol-workflow role split and test-first implementation. Root Astra owns design/acceptance, Sol workers implement their assigned file ranges; no recursive delegation.

**Goal:** Let a selected fixed-exit upstream be reached through an explicitly configured first proxy, without relying on company VPN administration.

**Architecture:** Optional per-profile pre-proxy settings provide the TCP tunnel to the pinned final proxy endpoint. Existing final-proxy TLS/authentication, same-route DoH, public-IP verification and forwarding continue inside that tunnel. No pre-proxy setting preserves current behavior.

**Tech stack:** Go1.27.3, MyGo0.7.3, existing private profile store and native desktop UI.

**Spec / accepted intent:** User asked to implement support for an existing proxy as a first hop; actual first-hop endpoint may be supplied later. Generic HTTP/HTTPS/SOCKS5 support is the implementation default, inactive until configured.

## Contract

- Public model additions: `Config.PreProxyURL`, `RemoteProfile.PreProxyURL`, `RemoteProfile.HasPreProxyCredentials`.
- Native input additions: `RemoteProfileInput.PreProxyURL`, `PreProxyUsername`, `PreProxyPassword`, `ClearPreProxyCredentials`. Private input fields follow the current non-serializing credential contract.
- Empty PreProxyURL disables the first hop. Disabling and explicitly saving clears its saved credentials; UI explains this. Merely editing/selecting fields never changes the active connection.
- Each final profile owns its first-hop endpoint and account. Blank account fields keep that hop's existing account only when its normalized endpoint is unchanged; replacing the endpoint requires replacing or clearing that hop's account. No credentials in URLs, public snapshots, errors or logs.
- Profile reader accepts existing strict v1 records as having no first hop. Write an explicit v2 format on subsequent profile mutation, keeping strict unknown/duplicate/null validation. Reading an unchanged v1 store need not rewrite it. New records must not silently load in an older version that ignores the first hop.
- Existing save/select/delete and advanced-settings paths preserve or explicitly revoke the complete chain and credentials. Old Web settings must round-trip the optional public endpoint rather than silently clear it; credential editing remains native profile UI.
- First-hop and final endpoints accept HTTP/HTTPS/SOCKS5 with explicit port, IPv4 or hostname. Proxy-server hostnames retain bounded system IPv4 resolution/pinning; business target names still use configured DoH through the final upstream.
- Both proxy endpoints are checked against ExitGuard's own listener after resolution. Reject a first hop identical to the final pinned endpoint. Distinguish validated proxy endpoints from business destinations, including legal loopback proxy endpoints.
- Every enabled-chain connection dials the first hop only. It tunnels only to the pinned final endpoint, then performs final authentication/TLS/CONNECT. Never bypass either hop or retry another route on failure.
- HTTPS at either hop uses normal certificate validation and the correct server name; nested TLS must work. Credentials are independent and sent only to their respective proxy handshake.
- First-hop destination refusal concerns reachability of the final proxy, so it is a route-wide error, never a target-local business failure. Preserve hard auth/TLS/protocol errors and classify genuine transient transport failures for existing verified recovery.
- Route fingerprint includes both normalized protocol/server-name/pinned-address endpoints when enabled. Recovery captures both accounts and restores only the exact prior chain and prior public IP.
- All sockets and both hop lifetimes obey request cancellation and session revocation. Existing total check/health/recovery deadlines are unchanged; no unbounded additive waits.
- Extend safe diagnostic stages/hop attribution so first-hop failures can be distinguished, without logging endpoint or account data.
- No OS proxy/VPN/routing/filter changes, no auto-discovery/import of company proxy settings, and no live credential/network changes by workers.
