# 验证记录与验收清单

此文件区分本地开发测试与实际网络保护。未执行的项目不等于通过。

## 交付状态：未激活开发版

当前版本不能作为已完成的双端强制保护工具使用。除了签名、固定出口及实机环境缺项，以下覆盖机制尚未完成：

- Windows 系统服务可能代目标程序发送 DNS 等流量，按目标可执行文件过滤不能完整约束这类代发路径。Chromium 启动参数能限制其解析器，但不能据此证明所有 Claude 非 Chromium 代码已受约束。
- 目标应用运行中更新或新增辅助程序后，当前静态路径策略没有持续发现并自动限制所有新增程序的完整机制。启动时检查已存在的辅助程序不能替代运行期版本覆盖。

这两项是实现范围的缺口，不只是尚未在实机上运行测试。已安装的规则只证明所列目标及明确协议路径的约束，不代表整个客户端的所有间接网络行为都已保护。

## 实机网络验收（尚未执行）

在准备好平台组件、固定出口及测试时段后，每个平台独立执行：

1. 记录选定应用主进程和辅助进程，核验系统过滤规则实际覆盖范围。
2. 通过实际 Claude 客户端、受保护浏览器执行登录、聊天、长连接、文件上传，并核验使用的出口。
3. 断开上游节点、本机中继、守护进程，分别检查新连接与已建立连接，不应出现未受约束的直连。
4. 飞连断开、重连、网络切换、睡眠唤醒后重新验证隧道身份；不能仅复用 utun 编号。
5. 验证 IPv4、IPv6、DNS、UDP/WebRTC、HTTP/HTTPS/WSS 的实现覆盖或明确拒绝。
6. 策略重载、节点变更、目标应用更新及可执行文件路径变化，验证状态失效与重新核验流程。
7. 验证系统规则只限制选定程序、可准确移除，不影响飞连本身与未选中的办公程序。

涉及公司连接中断的测试需要选择允许中断办公网络的时段。当前没有运行这些操作。

## 必须保留的边界

- 固定出口不是 Claude 账号不会被封的保证。
- 地址探测存在时间间隔，不能证明远端网关永不更换公网 NAT 地址。
- 本地代理与系统过滤保护的范围不同；代理停止后拒绝连接不能代替对应用其他连接的限制。
- 第一版受保护转发限定 IPv4 TCP；目标 IPv6 和 UDP 明确拒绝，避免跨地址族出现未校验出口。它不支持依赖 UDP 的实时音视频路径。
- 公司 VPN 分流可能让探测站点与 Claude 走不同路径；绑定已验证的接口仍需实际目标测试。
- 已选中的浏览器可执行文件可能包含多个普通窗口；用户需明确接受其程序范围，或使用独立浏览器安装。
- Windows 使用不关联 provider 的持久 sublayer/filter，避免官方文档对 provider 无关联服务时重启加载行为的歧义；过滤器归属仍依据唯一产品 GUID、严格元数据与完整规则读回。实际 BFE 重启/开机验收尚未执行。
