出口确认

候选探测只展示当前观察值，不自动认可固定性、不填写此栏，也不启动代理。多个已确认的 IPv4 可用逗号分隔。

短暂断线时

仅适用于代理转发方式。最多重试 3 次，必须重新确认同一路径和同一公网 IP 才恢复；账户、证书或出口身份异常仍需手动处理。仅对本次运行中已手动启动的会话生效；重开应用会载入已记住的账户，仍需检查出口并手动启动；未记住时需重新提交账户。手动暂停会取消恢复。

高级：本地 Mihomo 固定专用入口

使用你已有的本地传输。手动创建绑定固定单节点的专用 HTTP 监听；本应用不更改订阅或策略。

入口必须绑定具体单一节点。ExitGuard 的 17890 与上游的 17891 不可相同；此模式无需远程账户字段。
高级：公司飞连隧道

手动确认允许使用的隧道接口。本工具不更改飞连、系统代理、默认路由或公司凭证。

utun 编号不能证明公司固定出口；只在获准的网络路径使用。
高级：Clash / Mihomo 只读兼容检查

通用控制 API 无法证明入口绑定单一节点，此模式仅做兼容诊断，不能启用转发。需要转发时请选择固定本地专用入口。

可选：浏览器 / Claude 启动路径

Mac 会在启动或重新发现时检查常见安装位置的 Chrome、Edge 和 Claude Desktop。未找到时可在此添加实际可执行文件路径；不填也能手动使用代理。Claude Code CLI 和 URL Handler 不属于桌面端入口。

Windows 使用 chrome.exe、msedge.exe 或 Claude.exe；Mac 使用对应 .app 内的主可执行文件。严格阻断还需完整辅助进程范围。
高级：严格阻断与系统过滤

严格阻断独立于普通代理，需要真实 OS 过滤证据、完整目标及辅助进程覆盖。选择此方式不会安装任何规则；旧配置继续保留严格方式。

当前本地 Mac ad-hoc 应用没有可激活的 Network Extension，Windows WFP 尚需实机验收。系统代发 DNS、运行中更新的辅助程序仍有实现缺口，不能宣称完整应用保护。系统过滤按程序作用，同一程序的所有窗口可能受到影响。
高级：探测、出口内 DNS 与本机端口

目标域名通过选定上游使用 HTTPS DNS，只查询 IPv4 A 记录。远程代理服务器自身的主机名可用系统 DNS 定位，并固定本次路由的 IPv4；不修改系统 DNS。

保存服务器与设置；账户在上方单独提交，可选择本机明文保存。
