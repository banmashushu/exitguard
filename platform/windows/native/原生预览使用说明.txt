ExitGuard · Windows 原生应用预览（x64）

这份包用于在当前 Windows 桌面上测试 Chrome、Edge、Claude。
没有虚拟机；不切换整台电脑的代理、DNS、VPN或默认路由。
这是 preview-incomplete 开发预览，不是已经通过 Windows 验收的完整保护。
当前开发与自动测试在 Mac 上完成，Windows 文件仅交叉编译，不能据此推断实机成功。

先解压整个包。不要直接在 ZIP 里运行；不要分享含控制凭证的面板网址。
需要自行从官方发布页安装 Sandboxie Plus v1.18.8 x64（核心版本 5.73.8）。
本包不包含、不安装第三方程序，也不需要购买 SOCKS 注入许可。
官方发布页：https://github.com/sandboxie-plus/Sandboxie/releases/tag/v1.18.8

先做这一步（只检查，不改设置）

1. 从下面官方发布页安装 Sandboxie Plus v1.18.8 x64；这是让应用单独受限的 Windows 组件。
2. 完全退出 Chrome、Edge、Claude，包括后台窗口。
3. 双击“1-检查原生环境.cmd”。检查不会安装规则、改整机网络或启动这些应用。

显示“缺少组件”时，先检查官方组件是否正确安装。
显示“缺少分组”时，说明还需要下面的一次性配置；此时尚未启用应用保护。
显示“试用前置条件已核对”时，可以继续试用；这仍不代表通过了 Windows 实机测试。
不确定输出内容时，先停在这里。无需购买代理或登录 Claude 才能做这个只读检查。

下面是一次性配置的进阶步骤，可交给熟悉 Windows 的人协助。
请先阅读再操作；试用涉及的全局开关可能影响你已有的 Sandboxie 分组。

后续配置（进阶）

1. 先读本说明，再完全退出 Chrome、Edge、Claude（含后台进程）。不会自动关闭你的窗口。
   双击 1-检查原生环境.cmd。未准备好时显示 unavailable/incomplete，并说明停止的原因。
   它只读安装路径、数字签名/版本、运行时有效设置及真实 WFP 对象；不安装、不启用保护。
   未配置分组时显示缺少分组是正常现象。

2. 在 Sandboxie 的全局设置中手动审核 NetworkEnableWFP=y，然后重新加载配置。
   这是 Sandboxie 的全局开关，会改变已有 Sandboxie 箱的过滤方式；已有规则可能开始实际生效。
   若已有其他箱，先检查它们，必要时保留现状并停止这次测试。ExitGuard 不代你切换此全局设置。
   不需要改 Windows 系统代理、DNS、路由或其他应用设置。

3. 双击 2-生成待审核分组计划.cmd。它创建新的 ExitGuard-native-plan.json。
   用记事本审核 appendINI：只有 ExitGuard_Chrome / ExitGuard_Edge / ExitGuard_Claude 三个新箱。
   白名单只有 127.0.0.1:17890 TCP，其余 NetworkAccess 默认拒绝；关闭 DNSResolver IPC。
   启用普通安全箱、禁用规则特异性优先、降低管理员权限、拒绝软件更新器、独立箱内资料。
   不改已有箱，不共享你的日常浏览器或 Claude 资料；已有同名箱会拒绝覆盖。
   计划失败、发现未审核全局设置、外部 Include 或配置保护时，保留原配置，不要自行放宽规则。
   若计划已存在，先保留并自行删除旧计划，再重新生成；本工具不覆盖文件。

4. 只有审核计划后，才右击 3-应用已审核分组计划.cmd，选择“以管理员身份运行”。
   它校验当前 INI 与计划 SHA-256 一致，独占打开原文件，创建私有备份，然后仅在末尾追加新箱。
   备份位于同一目录：Sandboxie.ini.exitguard-哈希前缀.bak；可能含你原来的私有设置，不要分享。
   若配置在审核后发生变化，或 API 重载/有效策略/四个 WFP 回调检查失败，停止并显示原因。
   尚未验证时不启动任何目标程序。若显示“已追加但检查失败”，先核对现有箱与备份，不要重复追加。
   此步骤无需停用或改写任何已有箱；不自动安装驱动、不改全局 WFP。

5. 普通双击 4-打开应用保护窗口.cmd，保留这个窗口。
   它会先打开浏览器配置页面。保存上游代理、提交本次会话账户密码，确认期望公网 IPv4，检查后启动代理。
   请选“仅代理转发 / proxy-only”并保留本机端口 17890；旧严格模式不会自动降级。
   可在页面“可选启动路径”中先保存三款应用的完整 exe 路径，之后窗口会直接提供这些路径。
   配置完成后，完全退出 Chrome、Edge、Claude（包括配置页面所在的浏览器）。
   回到保留的“应用保护试用窗口”，按 1 启动 Chrome、2 启动 Edge、3 启动 Claude。
   路径已配置时按回车使用；否则直接输入完整 exe 路径，只用于本次。输入不会交给命令解释器。
   可以依次启动三款应用，控制窗口仍然可用：4 看状态、5 暂停、6 重新检查并启用、0 退出。
   如需改设置，先完全退出三款应用，再按 7 重新打开配置页面，完成后再退出浏览器回到试用窗口。
   此窗口不显示账户密码或控制凭证。Ctrl+C 可立即退出并关闭本次代理。
   不要在正在运行的 Chrome/Edge 配置页面中要求启动它自身；保留控制窗口就是为了避免复用已有窗口。
   每次启动都重新核验签名、运行时有效策略、四个内核回调与过滤器、已有进程和当前代理会话。
   失败即停止，不尝试普通直接启动。请在 Sandboxie 中确认实际父子进程归属；提交启动不等于实机验收通过。
   应用不兼容时，不要用宽泛放行、Breakout 或共享原资料来绕过检查。

适用范围

只有从原生预览入口新启动、并由 Sandboxie 实际归组的进程及其子进程属于这次测试范围。
普通桌面快捷方式、日常窗口、箱外更新程序和其他应用不自动归组；不要把它们当作受保护窗口。
不会强制接管所有快捷方式，不自动杀死已有实例，不修改它们的资料或网络设置。
指定“拒绝更新器”意味着箱内更新可能被拒绝；安装更新与新版本必须另行审核，更新后应重新测试。
代理可用时仍只转发 IPv4 TCP；IPv6、UDP/QUIC/WebRTC 直接连接应被拒绝，可能影响实时功能。
Claude 当前版本可能忽略 Chromium 参数或不兼容安全箱；登录、聊天、上传、更新均待真实设备验证。
上游必须实际提供静态出口；本工具不承诺绝对防封号、永久固定出口或逐连接不变。

开发者/协助人员的 Windows 验收附录

6. 保持面板代理启用，普通双击 5-1-启动箱外本地对照.cmd，并确认该进程未运行在任何 Sandboxie 箱内。
   它先读取已验证驱动对自身 PID 的确定箱外状态；任何未知错误均停止。
   只监听本机 TCP 17892（IPv4/IPv6）和 UDP 17893，每次实际收到 TCP/UDP 都记录计数和对端。保持此窗口；Ctrl+C 结束。
   若端口占用或 IPv6 不可用，此项缺少对照，不能把探针的连接失败算作“已阻断”。

7. 分别双击 5-2-观测Chrome箱.cmd、5-3-观测Edge箱.cmd、5-4-观测Claude箱.cmd。
   通过真实 Start.exe /box /wait 在产品箱中运行 ExitGuardNativeProbe.exe，不会箱外回退。
   探针会先读取自身内核归属及标志，再记录：
   - 当前明确 HTTP 代理到 HTTPS IP 查询的状态；预期可用且 IP 匹配你已确认的出口。
   - 17890 TCP 可连接；其他回环 17892、::1、直接公网 IPv4/IPv6 应无法连接。
   - UDP 本地回声的发送/接收结果；“socket 接收写入”不表示数据实际通过，必须结合箱外收到数据的计数/对端对照（UDP 输出包含本地端点便于对应）。
   - 随机改名的新子进程执行同样观测，记录实际 PID、箱名及进程标志。
   - GetAddrInfoW 与 DnsQueryEx 的实际返回；每次使用随机 example.com 子域名。
   输出只标为 incomplete。没有“导入报告以启用保护”入口。返回码/失败本身不构成过滤或 DNS 无泄漏证明。
   网络调用有上限；探针超过约 55 秒会退出并保留未完成结论。子进程输出可能先于父进程。

8. 需要懂 Windows 网络观察的人同时记录物理网卡/DNS Client broker 的实际行为（ETW/抓包/受控权威 DNS 对照）。
   GetAddrInfoW/DnsQueryEx 不得借箱外 DNS Client 产生直接外发。DNS NXDOMAIN 或缓存返回不算通过。
   当前包没有自动完成这项观察，不能据一行 ClosedIpcPath 或 DNS 错误宣布 DNS 已封闭。
   再测试暂停代理、结束 ExitGuard、上游断线/认证失败；被测箱进程应失去联网且不能绕行。
   用箱外普通应用做网络对照，确认未受影响；记录三款应用的登录、页面/聊天、上传及重启结果。
   以上缺一项都保持未完成。此包不会自动把代理状态变成 armed/完整保护。

撤回测试

完全退出三个产品箱中的程序。退出 ExitGuard（会话密码随进程消失）。
在 Sandboxie 中，仅移除新增的三个 ExitGuard_ 箱配置；箱内文件可能含独立登录资料，请自行保留或删除。
不使用整个旧 INI 备份直接覆盖正在变化的配置，以免丢失你之后的修改。
全局 WFP 如需恢复，先审核其他箱，再手动恢复原值；本工具不代改该开关。
